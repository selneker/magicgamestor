## Glitches du propriétaire (PL-005-FE-08c — commit 3)

Deux glitches signalés en relecture mobile, ni l'un ni l'autre touché par les correctifs
précédents (qui ne portaient que sur les tailles de cibles). Investigation : lecture de code +
**sonde navigateur** sur le build (lecture seule, `scripts/probe-g1-tmp.mjs`, hors dépôt).

### G1 — Retour à l'accueil via le logo : section blanche, rien ne s'affiche

**Cause confirmée** (sonde : chargement direct = opacité 1 ; retour via logo = opacité
**0**, sans style inline ; deep-link → accueil = idem) :

1. `html.has-js [data-hero-content] { opacity: 0 }` (`design-system.css:6664`, dupliqué dans
   `mg-brand.css:119`) cache le héros au boot ;
2. `runPageLoad` (`src/lib/slush.js:354`) est le seul code qui repasse l'opacité à 1 — il ne
   tournait **qu'une fois par rechargement** (drapeau `booted`, `SlushChrome.js:30,54`) ;
3. en SPA, le retour sur l'accueil remonte un **nouveau** nœud DOM → opacité 0 réappliquée,
   jamais animée → seul le fond crème du panneau reste visible.

**Correctif** (`SlushChrome.js`) : l'effet de route rejoue `runPageLoad` quand la vue montée
porte `[data-hero-content]` (garde `firstRoute` pour ne pas le rejouer au premier montage, où le
boot l'a déjà lancé ; gardes reduced-motion/capture dans `runPageLoad`).

**Vérification** (sonde sur le build corrigé) : retour via logo = **opacité 1** ✅,
deep-link → accueil = **opacité 1** ✅. `yarn build` ✅, tests 521/522 (échec connu) ✅.

Le « lag » perçu est un sujet distinct (coût de transition : `ScrollTrigger.refresh()` +
re-création des `SplitText` à chaque navigation, scroll reset non-Lenis) — documenté § G3,
non corrigé dans cette salve.

### G2 — « Preuve des clients » : impossible de regarder les photos

**Fonctionnalité absente, pas un bug d'affichage** (confiance élevée, code lu de bout en bout) :
après l'envoi, **aucun écran client** ne permet de revoir les captures de preuve uploadées —
- le seul endpoint qui sert une image de preuve est **admin** : `GET
  /admin/orders/{id}/proofs/{index}` (un utilisateur standard reçoit 403, test backend
  `tests/test_order_proof.py:324`) ;
- la visionneuse plein écran existe (`components/admin/ProofViewer.js`, zoom pinch/double-tap)
  mais n'est branchée que dans l'admin (`pages/admin/OrderProofs.js`) ;
- côté client, le suivi et l'historique n'affichent que le **compte** de preuves
  (« preuves : n ») ; la feuille d'envoi ne montre que les fichiers nouvellement sélectionnés.

Correctif propre = **endpoint client** `GET /orders/{id}/proofs/{index}` (owner-only) côté
backend **+** branchement de `ProofViewer` dans le suivi — le backend est hors de mon périmètre
frontend → **décision du propriétaire** (§ À décider). (Si le propriétaire parlait plutôt des
photos d'avis clients : la section avis de l'accueil n'en contient pas du tout — citations
texte uniquement, mention « avis d'exemple ».)

### G3 — Chasse générale (même famille, non corrigés, à vérifier en navigateur)

1. **Nav pilule — faux positif, clos après investigation approfondie** (5 sondes +
   capture) : il y a **deux navs distinctes** dans `Header.js`. `#navContainer` et la
   règle `#navContainer{transform:translate(0,-300%)}` (`design-system.css:6117`,
   globale — hors media query) appartiennent à la nav **desktop**
   (`.nav-w hidden min-[992px]:block`, `display:none` ≤991px). La pilule **mobile**
   visible (44×44, top 12 — capture `g31-after-spa.png`) est un markup séparé
   (`.nav-w--mobile`) jamais ciblé par cette règle. Les lectures computed
   `transform:none` s'expliquent : sous-arbre `display:none` (Chrome renvoie
   `none`, y compris pour un transform inline — vérifié corps/héros témoins lisent
   bien la matrice). Même si la règle s'appliquait : conteneur hauteur 0
   (enfants fixes) → déplacement nul. La pilule ne peut pas rester hors écran.
2. **Barres « collées en bas » menacées** : résolu par lecture — la coquille Layout
   `.page-w.min-h-screen.overflow-x-hidden` a déjà sa mitigation dédiée
   (`overflow-x: clip !important`, `index.css:359` — `clip` ne crée pas de scrollport, contra
   à `hidden`), et GSAP pose `overflow: "clip"` (slush.js:375, jamais `hidden`) sur `.main-w`.
   `position: sticky` reste donc ancré au viewport ; faux positif de la chasse.
3. **Scroll SPA non reset — CORRIGÉ (08f)** : au changement de page SPA, la
   position était perdue (l'utilisateur atterrissait en pleine page, sonde :
   2000 → 972, jamais 0). Cause exacte établie par trappe du setter `scrollTop`
   de l'élément de scroll : au commit, le document rétrécit, le navigateur
   **clampe** la position (interne, sans passage par le setter JS), puis Lenis
   **re-synchronise sa cible** sur la position clampée APRÈS l'écriture du
   reset de l'effet de route — l'écriture immédiate est écrasée dans la même
   frame. Correctif (`SlushChrome.js`) : reset immédiat + reset répété un
   `requestAnimationFrame` plus tard (une fois clamp et re-synchronisation
   passés), via `lenis.scrollTo(0, {immediate:true})` (fallback natif).
   Vérifié sur build : nav = 2000 → 1062 (frame transitoire) → **0 qui tient** ;
   retour accueil = scroll 0 + héros visible (pas de régression G1). Tests
   521/522 (échec connu).
4. Coût de transition de route (`ScrollTrigger.refresh()` + SplitText à chaque navigation).
5. Images d'événements sans `onError` (`Events.js:41`, `Home.js:425`) — cadrage produit :
   règle « image configurée avant tout fallback » → non modifié.
6. Reveals `once:true` : **faux positif, clos par sonde** (`probe-g36-tmp.mjs`) —
   au chargement direct ET au retour SPA, les cartes `[data-card-reveal]` lisent
   `opacity:1, visibility:visible` sans aucun scroll : le ScrollTrigger (start
   « top 80 % ») se déclenche immédiatement pour tout élément dont le seuil est
   déjà dépassé. Pas d'état caché résiduel.
7. `.is--transitioning` mort dans design-system.css (plus aucun JS ne le pose).
8. Loader de démarrage : 900 ms minimum s'ajoutent au premier écran (plafond 8 s, sans blocage).
